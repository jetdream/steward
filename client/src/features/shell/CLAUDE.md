# features/shell/ — the One-Home shell (XH-12)

**Purpose.** The home itself: the invariant chrome, the four fixed regions, and
the summon mechanics every other feature renders *into*. Nothing here knows what
a draft or a discovery is — features supply region content; this folder owns the
skeleton that never changes (DEC-18 protects the founder's spatial memory).

| File | Role |
|---|---|
| `Home.tsx` | the shell: chrome + the four regions in fixed order + the summoned pane. Presentational — content and callbacks come from props |
| `HomeScreen.tsx` | the DATA-BOUND home: session bindings (kill switch, org, sign-out) and region composition |
| `Chrome.tsx` | the invariant header — Pause · wordmark · Look-inside · Controls · Compose |
| `summon.ts` | the pure inertness/scrim rule, unit-tested (`summon.test.ts`) |
| `ShellPreview.tsx` | the dev-only `#shell` harness: the real shell with static content, so the e2e tier can assert its invariants without a session |

## Gotchas

- **There is no router.** Summoned views are client-local view state. A
  router-of-destinations here rebuilds the six-surface shell DEC-18 abolished;
  deep links ride the URL hash only.
- **The chrome is never a region**, so it can never be inerted — that is what
  keeps the AUT-3 kill switch reachable under a phone takeover (`summon.test.ts`
  asserts it).
- **`Home` omits an empty region entirely** rather than rendering a labelled
  empty box. A region with nothing in it yet must show nothing, not a placeholder
  implying work is happening there (VAL-6).
- The Pause control is bound to the SERVER's autonomy state from the shell's
  first increment (`useAutonomy`). A Pause on component state would look
  identical and stop nothing.
