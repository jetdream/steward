# features/ready/ — the Ready spine (UXS-3, APRS-1)

**Purpose.** Regions 1, 2 and 4 of `XH-12` — the pinned needs-you zone, the
finite clearable spine, and the caught-up terminus. The surface where most
founder time lives (`XH-1` / `XH-5`, the weekly visit).

| File | Role |
|---|---|
| `spine.ts` | the deterministic rules — what pins, what batch may touch, the header contract. Unit-tested |
| `ReadySpine.tsx` | `useReady` — the region contents the shell renders |

## Gotchas

- **A held card PINS; awaiting-picture does not.** A GR-3/GR-8 hold is a failure
  the founder must not miss, so it goes to the zone that cannot scroll away.
  Awaiting-picture is complete-but-blocked, not an error (GENS-4 says so
  explicitly), so it stays in the spine with Approve disabled and its reason
  stated.
- **The batch button states its exclusions BEFORE the tap.** "Approve all" that
  quietly leaves two cards behind reads as a failure; naming them makes the same
  behaviour read as the guarantee it is (APRS-1).
- **`batchExclusion` is a mirror, never the decision.** The server re-applies the
  same rule, so client drift over-promises in a label — it can never
  over-approve.
- **Never gate the region on `spine.length` alone.** Doing so destroyed the
  skip's "mind saying why?" prompt the moment the founder skipped their LAST
  card — the most common way a visit ends — so the CHTS-5 enrichment loop went
  silent exactly when it mattered. The region renders while cards remain OR a
  skip still owes its question.
- The skip reason is a SECOND call against an already-skipped item. One call with
  an optional argument is how "answering is a gift, never a toll" quietly becomes
  a toll again.
