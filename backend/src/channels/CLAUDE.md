# backend/src/channels/ — channel connect / OAuth (ONBS-4)

**Purpose.** Owns the DM-14 ChannelConnection lifecycle: the OAuth connect flow,
the encrypted-at-rest credential (SEC-10), and the deterministic health state
machine. This is the predecessor to publishing — the Publisher (ARC-18, I14)
reads a connection's health to activate a destination (PUBS-1).

**Place in the architecture.** A deterministic module (no LLM). Connect is
available in ANY order, ANY time, and is NEVER a gate (ONBS-4): zero connections
still let drafts flow; publishing simply waits for a `connected` connection.

**Credential secrecy (SEC-10, load-bearing).** The OAuth credential is sealed by
`secret-box` (AES-256-GCM) before it touches the DB and lives ONLY in the
server-side `credentialCipher` column. `list`/the router expose the SECRET-FREE
`@shared` `ChannelConnection` view (the DEC-39 secret-omitting projection); the
ONLY decrypt path is `credentialFor`, the Publisher's server-side read, which
returns null for any non-`connected` channel — a dead channel never hands out a
credential.

**Health machine (deterministic).** `connected | expired | revoked | error`. A
connect-time handshake failure THROWS (a plain-language retry) and persists
nothing. A LATER expiry/revocation (`markExpired`/`markRevoked`) flips the status
+ sets `statusReason` — the XO-4 needs-you card copy — so the founder never finds
a dead channel silently. Re-auth reuses `connect` (UPSERT on `(org, platform)`),
clearing the unhealthy state back to `connected`.

**Deferred.** The live Meta (IG-1) / X (IG-2) OAuth adapters need real app
credentials + redirect wiring (out of scope) — the dev connector stands in and
the port is stable, so a LIVE-connect smoke is deferred (GR-6: official APIs
only when they land). Subscription-eligibility gating for publishing is I14/BIL.
