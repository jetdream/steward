# backend/src/publishing/ — Publisher + Channel Adapters (ARC-18 / PUB)

**Purpose.** The delivery layer. Today it owns only the **PUBS-2 per-channel
technical profiles** — configuration, not code — consumed by the content engine
(GENS-2 adaptation + GENS-5 technical fit). Implements part of the behaviour spec
**PUBS** (`.spec/specs/pub-publishing.yaml`).

| File | Role | Spec |
|---|---|---|
| `channel-profiles.ts` | `channelProfile(platform)` / `allChannelProfiles()` — the SINGLE source of each channel's char limit, media requirement, link handling, and rate ceiling | `@implements PUBS-2 v1` |

**Config, not code (R-6).** Editing a limit here updates adaptation + fit with no
code change; profiles are per-channel and ISOLATED (the isolated-adapter posture —
an X policy change never affects the others). The four launch channels are
facebook_page / instagram / threads / x (PUB-4 LinkedIn is P2).

**LRN-20 split (downstream).** GENS-2 creative adaptation is the LLM step;
conformance to these limits is a DETERMINISTIC check (GENS-5) against this config —
a variant over a hard limit is regenerated/flagged, never shipped over-limit.

**Deferred (later increment).** Scheduling, the official-API publish adapters
(GR-6, Meta/X — dev-stubbed), the publish log (PUBS-3), the 24h pull + kill switch
(DEC-26/AUTS). No founder-facing surface yet — this is internal config the content
engine reads, so there is no router.
