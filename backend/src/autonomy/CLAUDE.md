# backend/src/autonomy/ — the Autonomy System (ARC-20)

**Purpose.** Governs what may publish WITHOUT founder approval, per content
category (Trust Levels, AUT-1), and owns the always-on kill switch (AUT-3). This
is the gate publishing (`../publishing`, I14) consults before any autonomous send.

**Place in the architecture.** A deterministic policy module (LRN-20 — no LLM
here; auto-publish is a level/latch decision, not a content judgment). Sits
between the content engine and the publisher: the publisher asks
`canAutoPublish` + `isPaused` before scheduling/sending.

**Structure.**
- `index.ts` — `createAutonomy({db})` facade + the pure `canAutoPublish` gate.
- Tables: `trust_level` (DM-9) + `publish_control` (the kill-switch scope ledger),
  in `@shared/db/autonomy.ts`.

**Active scope (P1b).** TL0 (launch — approve everything) + the kill switch.
The kill switch is a P0 chrome affordance (UXS-6): global (`killSwitch`) or
per-channel (`pauseChannel`), always instantly reversible (`resume`). Pausing
flips in-flight `scheduled` ChannelVariants → `paused` (DM-5); resume flips back.

**Deferred (semantics pinned, NOT wired).** TL1/TL2 + promotion/auto-demote
(AUTS-2, P2) and the permanent TL1 external cap (EXTS-3). `trust_level.level`
and `vetoModel` (DEC-26) already carry the full enum so promotion is a data
change, not a schema change.

**Guardrail relationship.** Autonomy NEVER overrides a guardrail: a GR-3/GR-8
hold or a vetoed item is `canAutoPublish=false` regardless of level. The hold
itself is owned by the pipeline (PIPE-3), not here.

- `@implements AUTS-1 v1` (Trust Levels — TL0 launch + the gate)
- `@implements AUTS-3 v1` (the kill switch)
