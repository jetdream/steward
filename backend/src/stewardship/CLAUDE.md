# backend/src/stewardship/ — donor-lifecycle read (ARC-15 / STW)

**Purpose.** STW-1 makes gratitude/impact posts first-class overlay categories
from week 1. It owns NO separate planner (no double-ownership, STWS-1): the
guarantee is REALIZED by the **GENS-1 planner quota** — the ≥1 impact/gratitude-
per-trailing-28-day reservation is a deterministic PLAN-TIME slot designation
(`@backend/content/planner`, `designateAndSchedule`). This module adds the READ
the weekly-visit home shows (XH-1): the posting streak (the G-4 north-star metric)
and whether the trailing window carries an impact/gratitude post.

| File | Role | Spec |
|---|---|---|
| `index.ts` | pure `computeWeekStreak` + `hasImpactRhythm`; `createStewardship({db}).status` | `@implements STWS-1 v1` |

**Deterministic counts (LRN-20).** The streak counts consecutive trailing 7-day
weeks with ≥1 PUBLISHED variant (DM-5); the rhythm counts impact/gratitude-
DESIGNATED items in the trailing 28 days — plan-time designations + delivery
facts, never an LLM classification of realized prose (whether the prose faithfully
realizes its overlay is a soft VAL/fit check, not this count).

**No new entity.** Reads existing DM-5 rows (published `channel_variant`s +
`impact_gratitude`-designated `content_item`s).

**Deferred (P1, not in the P1b slice).** STWS-2 milestone recaps (a campaign
end-date / founder "we hit a milestone" tap → a thank-you + impact-recap package
via GENS + PRO-1 material request) and PROS-3 ask-hygiene (flag asking-without-
reporting) — the GENS-1 quota alone carries the P0 STW-1 guarantee.
